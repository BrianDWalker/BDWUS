# Data source status

The current repository has no mockData.js or src/data directory. Customers, catalog services/rate plans, quotes and opportunities already use sales/billing APIs; invoices and adjustments use billing-workflows SQL APIs. Customer 360, operations, knowledge and reports also use APIs. The old migration map in fc-gpt docs describes an earlier revision.

This change makes API defaults same-origin (hosting PR), exposes paginated SQL view reads for subscriptions, payments and usage, and adds tabs with loading, empty, error and retry states. Existing Billing errors were held in state without being displayed; that is fixed. The approved SQL views exist in dev and prod and return the four explicitly approved demo records in each database: 1 subscription, 1 payment and 2 usage events. The UI never fabricates fallback billing rows.

billing_facts_proposal.sql was reconciled against the production catalog and applied as an additive migration after owner approval. It follows the captured production baseline in the dev manifest. No new procedures are needed for these read pages. Existing ms.vPricingContext is synthetic and needs a separate owner-reviewed real-data definition after the original schema is available. The billing-facts UI/API and SQL views were checked with approved demo records; this does not establish real payment processing or production billing integration.

billing-demo no longer exists. The current bootstrap_demo_data.py seeds SQL directly through the shared managed-identity connection and now refuses prod. No Blob upload path exists. No replacement CSV/Blob pipeline is introduced because the current repo has no consumer. Dev was built and explicitly seeded; runtime grants were applied to both environments. Production customer data was not copied or modified.
