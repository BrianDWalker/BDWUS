This secret is an unavoidable Easy Auth registration credential, referenced from Key Vault; SQL and registry access use managed identity. No secret value goes into Bicep, azd environment files, .env files, GitHub secrets or command-line arguments. Use the Azure portal secret editor or a protected temporary file and `az keyvault secret set --file <protected-file> --output none` after approval.

Container Apps Easy Auth owns sign-in redirects and injects identity headers. The API validates the tenant and derives authorization from the platform's role claims; it ignores browser-selected roles and demo bearer tokens in Entra mode. Never expose the container port through an ingress that bypasses Easy Auth. `/health` is the sole anonymous liveness endpoint. Local demo authentication requires explicit PLATFORM_AUTH_MODE=local and must never be configured on an Azure app.

No workflow provisions resources or applies SQL.

Create a deployment identity per environment with federated credential issuer `https://token.actions.githubusercontent.com`, audience `api://AzureADTokenExchange`, and subject `repo:BrianDWalker/BDWUS:environment:dev` (or `:prod`). Assign the reviewed BDWUS Portal Deployer role only on that environment's existing app, managed environment and runtime identity. On bdwuscr, assign registry ARM Reader plus conditional Repository Writer for bdwus-portal, using infra/github-deploy/main.bicep. Do not restore resource-group Contributor or AXIOM registry AcrPush. These deployment identities are separate from runtime identities. Client/tenant/subscription IDs are identifiers, not secrets. Configure production required review before enabling the workflow.

If a deployment identity is ever deleted and recreated, it keeps its resource name but receives a new principal ID. Before rerunning the identity template, inventory the old principal's assignments on the app, managed environment, runtime identity and registry. Obtain owner approval for the exact stale assignment IDs, remove those stale assignments, and then deploy the replacement assignments through Bicep. The three app/environment/runtime assignment names use the stable identity resource ID, so they cannot be updated in place to a different principal. Do not restore broad roles to bypass this check. No identity recreation or stale-assignment deletion was needed in the completed rollout.
